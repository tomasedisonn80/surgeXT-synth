## Corrected dependency: coefficient-source table rebuilds

The caches cover numeric coefficient inputs and sample-rate inverse, but the
underlying coefficient calculations also read storage lookup tables. The synth's
new `sampleRateReset()` invalidations cover its normal rate-change path. Two
other paths can rebuild those tables without invoking that hook:

- `SurgeFXProcessor.cpp:258–269`: `prepareToPlay()` calls
  `storage->setSamplerate(sr)` directly for an already-loaded effect.
- `SurgeStorage.h:1964–1974`: `retuneTo12TETScaleC261Mapping()` calls
  `init_tables()` directly; callers include UI/menu and patch-loading code.

`SurgeStorage.cpp:3081–3105` rebuilds tables even for an unchanged rate.
`init_tables()` at line 3214 regenerates `table_dB`,
`table_pitch_ignoring_tuning`, and fractional pitch tables. Biquad frequency and
peak-EQ calculations consume those tables through the adapter in
`libs/sst/sst-filters/include/sst/filters/BiquadFilter.h`.

A rebuild under a different floating-point context can therefore change table
bytes while every current cache key remains equal. Ordinary nearest-rounding
rebuilds are numerically identical; this is a source-supported missing
invalidation path, not a reproduced runtime failure.

Implemented `SurgeStorage::coefficientTableGeneration`, initialized to zero as a
member before the constructor body calls `init_tables()` (`SurgeStorage.cpp:140`).
Each completed `init_tables()` increments it exactly once (`SurgeStorage.cpp:3264`),
covering construction, accepted `setSamplerate()` calls (including the same rate),
and standard-tuning restoration. It is never reset during the storage lifetime.
The unsigned counter wraps modulo 2^64; correctness assumes no still-live cache
spans an entire wrap, a practical invariant even with pathological rebuild rates.

Each of the three effects reads the generation once at its existing coefficient
update cadence and includes it in `refreshAll`, alongside the existing numeric
inputs and sample-rate inverse. It caches the observed generation after updating
targets. The initially invalid cache still forces first use, irrespective of
the counter value. No audio history, smoother, processing cadence, or band
deactivation behavior was changed.

The revision is an atomic uint64 with relaxed operations, following existing
storage uint64 atomics. Only `init_tables()` performs a read-modify-write; effect
updates perform one load. The standard-tuning UI callback at
`SurgeGUIEditorMenuStructures.cpp:428–438` has no adjacent serialization guard,
so an atomic avoids adding a scalar counter data race. This is cache invalidation,
not safe publication of the non-atomic tables. Existing callers must still
serialize table mutation against DSP reads; this patch does not repair existing
table races. It adds no explicit lock or allocation. Lock-free atomic behavior
should be retained when supporting a new target ABI.

Recommended regression: warm an effect,
rebuild storage tables at the same rate under directed rounding without calling
the effect reset hook, restore the normal callback environment, then compare the
complete output against the baseline. Also exercise direct standard-tuning
restoration without an effect reset hook.

The effects plugin also uses `juce::ScopedNoDenormals` rather than the synth's
round-to-nearest `FPUStateGuard` (`SurgeFXProcessor.cpp:316`). Equivalence evidence
should describe its floating-point assumptions; a host changing rounding mode
between callbacks is an additional context change not represented in cache keys.

## Reviewed behavior without another blocker

- The per-block lowcut omega hoist uses identical storage and inputs for all
  cascade stages and retains every coefficient update and processing call.
- Cache comparisons preserve signed-zero changes and reject NaN equality.
- Initialization, suspension, and the parent's explicit same-rate reset hooks
  invalidate caches. The Conditioner first-processing invalidation closes the
  already-reported outside-callback initialization case.
- Effect recreation starts with invalid caches. Preset loading without recreation
  updates the existing parameter data, which the per-band keys observe.
- Deactivated bands retain coefficient updates at the original cadence. Ringout
  and coefficient smoothing remain in the original processing paths.
- Ordinary custom tuning changes only tuned tables; these effects intentionally
  use pitch-ignoring-tuning tables.
