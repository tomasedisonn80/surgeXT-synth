# Wave 3 / agent 15 — hosted callback regression coverage

Implemented `XTTestCpuProcessing.cpp` and registered it in the native XT test
executable. The tests call the actual `SurgeSynthProcessor::processBlock`; there
is no copied implementation of its sample loop.

## Cases

- Compare complete stereo and six-channel output for the same fixed MIDI
  timeline rendered with callback sizes 1, 32, 64, 128 and mixed odd sizes.
  Events include sample positions 0, 1, 31, 32, 63, 127, 511 and 767. Empty
  callbacks are interspersed in the comparison paths.
- Use fresh guarded backing arrays on every callback. Check both buffer canaries,
  finite outputs and replacement of all sentinel samples.
- Verify disabling engine extra outputs clears their host buses and preserves
  the main mix.
- Render real Audio Input oscillators with aliased mono/stereo host input.
  Compare aligned callbacks in nonlatent mode and both aligned/odd callbacks in
  explicit one-block latent mode. Check the engine's retained input samples
  against the original deterministic input, including mono duplication and the
  expected one-block delay.
- Verify a zero-length callback consumes queued MIDI without advancing transport
  or touching canaries, then resumes rendering on a one-sample callback.
- Exercise bypass drain/clear, resume, and host reset with guarded output buffers.

The fixture uses fresh processors, deterministic reseeding after preroll, a
retriggered sine or Audio Input oscillator, zero drift, disabled effects and an
isolated user-data directory. OSC startup preferences and storage flags are
disabled explicitly. It leaves engine block size and sound-quality settings
unchanged.

## Integration and validation status

All five tests carry `[cpu-processing][reference-workspaces]`, so the existing
`[reference-workspaces]~[reference-render]` native workflow selection includes
them without a workflow edit. They can also be selected with `[cpu-processing]`.

Scoped `git diff --check` passed. Compilation and execution are pending the
coordinator's native build/CI; no runtime pass or performance improvement is
claimed by this report. This covers the JUCE float callback and does not claim a
commercial DAW or CLAP direct-process end-to-end validation.
