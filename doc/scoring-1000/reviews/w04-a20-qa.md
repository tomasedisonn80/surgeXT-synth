# Wave 4 / Agent 20 — Independent audio QA harness audit

Reviewed `scripts/scoring/qa_bank.py` and `AGENTS.md`. This assignment inspected
the implementation and used isolated synthetic PCM/function probes. It did not
run the full bank, change the harness, or audition the presets.

## Two material findings before the full-bank run

### 1. Attack response can be falsely attributed to the macro

The Attack endpoint deliberately holds the note longer to allow its extended
attack to develop. The default fixture holds the note for less time. However,
`compare_waveforms()` compares the entire common file length, including the
period after the default's note-off while the Attack test note is still held.
`compare_features()` also compares envelopes normalized over different active
window durations. Either difference can report a measurable response even when
the instrument ignores the Attack macro entirely.

A synthetic probe with the same 220 Hz voice, attack and release in both tests,
with **no macro behavior**, produced these results:

| Measurement | Result |
| --- | ---: |
| Default hold / Attack-fixture hold | 3 s / 8 s |
| Original waveform relative RMS delta | 1.189384 |
| Original spectral/envelope feature distance | 0.239963 |
| Existing waveform / feature thresholds | 0.001 / 0.002 |
| Delta over the matching first three seconds | 0 |

**Recommended correction:** compare Attack only over a matching pre-note-off
window, or render a separate baseline with identical longer MIDI timing. Do not
use feature distances calculated from differently timed active windows as a
fallback. Report the comparison window so the evidence remains interpretable.
This fixes attribution; measurable change still does not certify musical value.

### 2. A long silent tail can dilute the reported DC level

`channel_dc` is the mean over the entire rendered file. The DC failure check
uses only this mean. A long quiet tail can therefore hide an excessive offset
during the held note.

A probe containing **0.01 DC for three seconds** followed by **30 seconds of
silence** reported channel DC **0.00090909**, below the 0.003 threshold. The
existing audit returned no failures. This was a diagnostic synthetic fixture,
not evidence that any actual preset has this defect.

**Recommended correction:** retain the whole-file metric and add per-channel
DC over the active-note window, applying the existing threshold to that window
as well. A windowed or steady-state measure may provide further diagnostics,
but a new threshold is not needed to correct this demonstrated blind spot.

Root acknowledged both findings and is implementing these corrections. The
corrections were not independently retested within this assignment; subsequent
recorded checks must establish their final behavior.

## Coverage and binding checks that passed inspection

Function-level enumeration of the current complete manifest confirmed:

- **1,000 presets**, each with **23 planned scenarios**.
- Every polyphonic stress fixture has **16 unique notes**; every note stays
  within the preset's declared range.
- Monophonic stress fixtures correctly contain one note.
- Native report row counts, output identities, PCM sample counts, native
  success and loaded names are checked; a nonzero native exit fails the run.
- Nonfinite audio is counted before a diagnostic-only replacement copy is
  created, so nonfinite samples cannot become a passing result through cleanup.
- Sample clipping, silence and release checks are independent of normalization;
  the harness does not normalize or limit the tested audio.
- Reusable successful results bind preset bytes, the catalog entry, planned
  fixtures, the QA script, renderer binary, configuration and NumPy version.
  Patch changes during rendering and renderer replacement during a run are
  checked. Failed caches are not reused as passes.
- Fresh engine instances and repeated defaults support controlled comparison.
  The repeated-default difference is retained instead of assuming determinism.

## Explicit scope limits to preserve in delivery

- Hard-versus-soft velocity response is measured, but inadequate differentiation
  remains a warning. A report with warnings should not be presented as uniform
  expressive approval.
- Mono scenarios test a single note; they do **not** test overlapping legato,
  note priority, portamento transitions, sustain-pedal behavior or repeated-note
  rearticulation. Polyphonic fixtures similarly do not establish a complete
  voice-stealing or pedal-transition test.
- Tempo fixtures check output integrity at 60 and 180 BPM. They do not prove
  that a specified pattern has the intended musical subdivision or phase.
- The 16-note stress and aggressive-macro chord are separate fixtures; they do
  not jointly exercise all 16 notes with every aggressive macro at its maximum.
- Peaks are explicitly **sample peaks**, not reconstructed true peaks.
- Native save/reload checks identity, not complete semantic serialization
  equality. Independent serialization, static-bank and package audits remain
  necessary.
- Exact audio hashes and coarse fingerprints assist duplicate review. Different
  hashes do not prove perceptual distinction, and the fifth gate is evidence
  completeness rather than a listening review.
- Human musical audition remains pending and composer endorsement is not
  claimed. This audit does not change either status.

## Assignment outcome

Completed the independent audit and reported two reproduced measurement defects
before the full-bank run. No preset, generator, renderer or QA implementation
was modified by this agent. Only this review document was added.
