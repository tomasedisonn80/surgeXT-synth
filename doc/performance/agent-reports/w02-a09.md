## Why skipping unused LFO2–6 preparation is unsafe

`SurgeVoice::calc_ctrldata` prepares formula inputs every block even when an LFO
has no active modulation destination. Those cached inputs have another reader:

1. `SurgeSynthesizer::reclaimVoiceFor` updates the voice and calls
   `SurgeVoice::retriggerLFOEnvelopes`.
2. That function calls `LFOModulationSource::attack` for every key-triggered LFO,
   including LFOs currently absent from the modulation routing mask.
3. Formula attack calls `Surge::Formula::prepareForEvaluation`.
4. `prepareForEvaluation` passes cached macros, controllers and voice inputs to
   the formula's Lua `init(state)` function.

An unused formula can therefore capture an input during a retrigger and expose
that captured value after a route is added later. Skipping preparation produces
stale inputs. Refreshing inputs immediately before attack is not an equivalent
repair: the existing path exposes the previous preparation snapshot, including
voice-key state from before reclamation.

### Concrete regression recipe

Use voice LFO2 in key-triggered Formula mode with no destination initially:

```lua
function init(state)
    state.captured_macro = state.macros[1]
    return state
end

function process(state)
    state.output = state.captured_macro
    return state
end
```

Hold a voice, change macro 1, and render enough blocks for smoothing and the
formula-input snapshot to update. Reclaim that voice through a supported
repeated-key/mono retrigger mode. Then add an LFO2 modulation route and compare
the formula output and rendered audio with the original implementation. Repeat
with cached controller and voice inputs. This is a proposed regression fixture,
not a claimed executed test.

## MTS-ESP side effect

The voice overload of `setupEvaluatorStateFrom` calls `SurgeVoiceState::getPitch`.
With an active MTS-ESP client, that function updates `keyRetuningForKey` and
`keyRetuning`. Later in `calc_ctrldata`, `applyModulationToLocalcopy` can advance
MPE pitch-bend smoothing before `update_portamento` calls `getPitch` again.
Removing the earlier call can therefore move the tuning snapshot relative to
MPE smoothing. A future optimization must preserve that ordering, especially
when a reclaimed voice changes key and retuning is snapped rather than constant.

## Macro RTTI decision

Production macro slots are populated with `MacroModulationSource` instances in
the synthesizer constructor, and macro swapping preserves their types. Calling
the base virtual `get_output(0)` would match those normal instances.

However, `setupEvaluatorStateFrom` currently uses a
`dynamic_cast<ControllerModulationSource *>` and leaves the destination value
untouched for null or non-controller slots. A plain null check would read a
non-controller slot instead and change the helper's semantics. The cast is
retained; no unchecked downcast or narrower fixture contract was introduced.

## Future work

A shared formula-input snapshot could remove repeated lookups while keeping
every evaluator's observable snapshot current. It needs explicit handling of
null/non-controller slots, retrigger timing, route activation, MPE and MTS-ESP
before implementation. Retain the original preparation path until those
invariants have native differential coverage.
