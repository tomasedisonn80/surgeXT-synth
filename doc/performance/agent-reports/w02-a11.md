# Wave 2, agent 11 — benchmark comparison and evidence checks

Implemented `scripts/performance/compare.py` and its standard-library unit tests.
The comparator accepts schema-1 `surge-cpu-bench` reports, checks every required
metadata field and scenario, recomputes timing summaries, and rejects invalid,
nonfinite, incomplete, duplicate or inconsistent input. Different source commits
are allowed; compiler, build configuration, Lua/LTO settings, sample rate, block
size, seed, preroll, durations, repetition counts and fixture configuration must
match. Scenario ordering may differ, but missing, extra or repeated names fail.

Every repetition must report the same PCM fingerprint, and both builds must
agree. Supplying both PCM directories additionally verifies the complete bytes,
their expected lengths, finite samples and their binding to the report's FNV
fingerprint; the comparison records a SHA-256 digest of the matched audio. Hash
comparison without full PCM is explicitly labelled as weaker evidence.

The JSON result retains timing arrays and ranges, reports held/released medians
and real-time percentages separately, and calculates the percentage reduction in
median elapsed time. No regression threshold is imposed by default. An explicit
`--max-regression-percent` gate fails if either window exceeds the chosen limit.
Offline wall time is not described as DAW callback deadline evidence.

Validation: `python -m unittest discover -s scripts/performance -p test_compare.py -v`
passed all 25 tests. Tests cover incompatible metadata, scenario sets, corrupt
timing summaries, false determinism, changed hashes, missing/truncated/replaced
PCM, nonfinite samples, duplicate JSON keys, command-line output and preservation
of input reports. All unit-test timing fixtures are synthetic and provide no CPU
performance result. Compiled baseline/candidate evidence remains the coordinator's
integration task.
