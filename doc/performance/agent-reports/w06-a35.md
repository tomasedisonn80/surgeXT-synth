## Parameter and processing paths

- `Effect::Effect` binds `pd_float[i]` to the effect parameter's entry in the
  supplied `pdata` array. In the synthesizer this is `patch.globaldata`.
  `SurgeSynthesizer::process` copies base parameters, then adds global modulation
  into that array before processing effects. The regular Conditioner, Graphic EQ,
  and Parametric EQ cache keys all read `pd_float`; none substitutes raw stored
  patch values for the modulated values. Parametric EQ retains its original raw
  patch reads only in the distinct initialization branch.
- Conditioner still calls `setvars(false)` once per processed audio block. Both
  EQs retain `if (bi == 0) setvars(false)` followed by
  `bi = (bi + 1) & slowrate_m1`; `slowrate` remains eight. Cache invalidation does
  not move that sampling boundary or reset the counter during a rate change.
- All bands update coefficient targets at the existing cadence even while their
  deactivation flags suppress audio processing. Re-enabling with an unchanged
  target therefore retains the original target and smoothing state. Bypass still
  works at the engine/effect-dispatch layer; changed parameters are read at the
  same next normal control update when processing resumes.
- Gain, mix, stereo width, balance, compressor attack/release, detector history,
  lookahead delay and meters remain outside coefficient reuse. Their per-block
  or per-sample work is unchanged. `Effect::process_ringout` and Conditioner's
  `process_only_control` were not changed. In particular, the existing control-only
  Conditioner path never updated these coefficients; the resumed audio path does.
- The pinned Biquad `newValue` assigns a target. Its smoothing advances in sample
  processing. Skipping an identical target assignment does not skip smoothing.
  Deactivated bands retain the same original lack of sample processing.

## Lifecycle invalidation

All three `sampleRateReset()` overrides invalidate only the cache. The base
implementation was empty, so no inherited reset behavior is lost. All three
`suspend()` implementations call `init()`. The EQ initialization branches
invalidate before the original coefficient setup/filter suspension and set
`bi = 0`; their next processed block therefore restores targets. Conditioner
forces coefficients during initialization, then invalidates afterward so the first
processed block recalculates in its callback environment.

Numeric rate, storage table generation and floating-point environment keys cover
changes occurring without those hooks. Exact float comparisons retain signed-zero
changes and reject NaN cache hits. The table generation is an invalidation signal,
not synchronization for concurrent table mutation.

## Concrete coverage limits

The coefficient ramps modify `FxStorage` values and pass through the engine's
normal parameter copying. They do not specifically install a changing modulation
route while its base parameter stays fixed, and they do not drive a real VST/CLAP
host automation queue. The reviewed `pd_float` data path supports those cases,
but the fixture results should not be described as exhaustive host automation
validation. A future targeted route-only fixture would guard against accidentally
changing cache keys to raw patch values. No current source defect warrants a
production change from this review.

The fixtures vary rate/reset phase offsets. Disable, bypass and rounding events
use fixed block boundaries; they are broad lifecycle coverage, not exhaustive
combinations of every event and control phase. Dynamic gain/mix controls are
unchanged and are not comprehensively automated by this particular suite.
