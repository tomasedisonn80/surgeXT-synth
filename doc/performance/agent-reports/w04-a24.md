# Wave 4, agent 24 — continuous correctness gates

Role: systems engineer and VST CI specialist.

## Implemented

- Added `.github/workflows/cpu-performance.yml`, triggered by relevant source,
  dependency, build and performance-tool changes, plus manual dispatch. The job
  runs on Ubuntu 24.04 with `contents: read`, nonpersistent checkout credentials,
  a 45-minute bound and two build workers.
- The workflow configures the headless Release/LTO preset with explicit PUC Lua,
  disabling the general engine test runner and scoring targets for this bounded
  job. It builds only the CPU benchmark, modulation differential test and DSP
  regression renderer. Existing workflows continue to cover hosted processor
  tests and distributions.
- Registered `cpu-modulation-mask` and `cpu-smoke` with CTest. The smoke gate
  requires Python 3.10 or later, runs serially, and has a 300-second timeout.
- Added `scripts/performance/run_smoke.py`. Each run uses fresh temporary PCM
  directories, validates ten benchmark scenarios with two deterministic
  repetitions, and verifies the length, finite samples and reported fingerprint
  of all 63 DSP lifecycle fixtures. JSON, logs, binary hashes and per-file SHA-256
  summaries are retained; temporary PCM is removed afterward. Repeated CTest runs
  therefore do not collide with the renderer's nonempty-output protection.
- Added only the three permitted offline paths to release workflow exclusions:
  `doc/performance/**`, `scripts/performance/**`, and `src/performance/**`.
  Production source and root build configuration changes still trigger platform
  release builds.

## Meaning of a passing gate

This is a single-build correctness and deterministic rendering smoke check.
It does not compare baseline and candidate revisions, establish a performance
improvement, impose a timing threshold on a shared runner, or establish host
callback deadline behavior. Those conclusions require the separate paired
measurement and baseline PCM comparison performed by the coordinator.

## Validation performed

Python byte compilation and AST parsing passed. The workflow parsed as YAML;
read-only permission, Ubuntu runner and timeout values were checked. Scoped
whitespace checks passed for all changed/new implementation files. Native builds,
CTest execution, workflow execution, commits and publication were deliberately
left to the coordinator, as assigned. No runtime or CI success is claimed.
