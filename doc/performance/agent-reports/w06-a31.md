## Architecture evidence

- The pinned `libs/sst/sst-basic-blocks/include/sst/basic-blocks/simd/setup.h`
  defines `SST_SIMD_ARM64` for `_M_ARM64EC` as well as ordinary ARM64 macros.
  Selecting ARM before `SST_SIMD_NATIVE_X86` correctly avoids the compatibility
  macro ambiguity on ARM64EC.
- [Microsoft's ARM64 intrinsic reference](https://learn.microsoft.com/en-us/cpp/intrinsics/arm64-intrinsics?view=msvc-170)
  identifies `_ReadStatusReg(int)` as the MRS intrinsic, declared through
  `intrin.h`.
- [LLVM's primary `arm64intr.h` source](https://clang.llvm.org/doxygen/arm64intr_8h_source.html)
  defines the intrinsic register encoding and binds FPCR to
  `ARM64_SYSREG(3, 3, 4, 4, 0)`. Applying that encoding gives
  `0x4000 | 0x1800 | 0x0200 | 0x0020 = 0x5a20`, matching the implementation.
  This encoding is the intrinsic argument, not the complete instruction field.
- GNU/Clang ARM64 uses the same `MRS ..., FPCR` form already present in the
  pinned `sst-plugininfra/src/cpufeatures.cpp`. Full FPCR is conservative: it
  includes controls, while cumulative exception status uses FPSR.
- Native x86 retains MXCSR rounding/FTZ/DAZ (`0xe040`), excluding sticky status.
  GNU/Clang additionally reads x87 precision/rounding (`0x0f00`), covering
  control-state dependencies in math-library code. Legacy 32-bit MSVC and
  unsupported architectures conservatively disable coefficient reuse.

These checks establish the source and encoding rationale. They do not replace
compilation with the repository's actual MSVC, Apple and Linux ARM toolchains.

## Executed native probe

Compiler: `g++ (Debian 14.2.0-19) 14.2.0`.

A small standalone program included the actual production header and was compiled
with `-std=c++20 -O2 -msse4.1 -mfpmath=sse`, the repository's common and SST/SIMDE
include paths, `SURGE_COMPILE_BLOCK_SIZE=32`, and `LINUX=1`.

**Passed 21 native assertions:** supported-state reporting; invariance when only
MXCSR sticky exception flags change; changes for the three nondefault rounding
encodings, FTZ and DAZ; changes for x87 rounding and precision controls; read-only
behavior for each control setting; return to the original key after restoration.
The probe restores both control registers through a scoped destructor.

Probe source SHA-256: `1bf59429ae98d9a37a60b3bee61ba28dbc3d0acd676c07940365a33576537788`.
The temporary probe is not part of a plugin or a benchmark. No CPU-speed claim
is made from these assertions. The coordinator's full PCM regression supplies
separate effect-level evidence for mode transitions.
