## Actual negative cases

Every negative invocation exited **1**. Existing protected files were initialized
with non-text sentinel bytes and compared byte-for-byte after execution. File
collisions were tested before any patch parsing, so malformed sentinel contents
could not conceal an overwrite by producing an unrelated patch error.

| Group | Cases | Observed protection |

| Report aliases input patch | 3 | Exact path, hardlink and symlink rejected; input unchanged. |
| Generated PCM aliases input patch | 3 | Exact path, hardlink and symlink rejected; input and existing report unchanged. |
| Report aliases generated PCM | 3 | Exact path, hardlink and symlink rejected; protected files unchanged. |

| Invalid sample rate | 6 | 11999, 192001, 48000.5, NaN, positive infinity and negative infinity rejected. |
| Invalid repetition count | 5 | 0, -1, 31, 1.5 and NaN rejected. |
| Invalid held duration | 6 | 0, -1, 30.001, NaN, positive infinity and negative infinity rejected. |
| Invalid tail duration | 4 | 0, 30.001, NaN and infinity rejected. |
| Invalid argument structure or fixture input | 10 | Duplicate output/repetitions, missing final value, missing value before an option, unknown option, unknown scenario, missing data directory, missing patch, numeric suffix and missing required output rejected. |

Collision invocations used this argument shape, substituting the aliased paths
described above:

```text
surge-cpu-bench --output REPORT --pcm-dir PCM_DIR --scenario patch \
  --seconds 0.002 --tail-seconds 0.002 --repetitions 1 --patch INPUT
```

Report-versus-PCM cases used `--scenario idle` without `--patch`. Argument
rejections used `surge-cpu-bench --output EXISTING_SENTINEL_REPORT` followed by
each invalid option. The missing-required-output case omitted that option.

## Accepted boundaries

Both invocations below exited **0**:

```text
surge-cpu-bench --output REPORT --pcm-dir PCM_DIR --scenario idle \
  --sample-rate 12000 --repetitions 2 --seconds 0.002 --tail-seconds 0.002
surge-cpu-bench --output REPORT --pcm-dir PCM_DIR --scenario idle \
  --sample-rate 192000 --repetitions 2 --seconds 0.002 --tail-seconds 0.002
```

Each JSON report passed `compare.validate_report`. Comparing each report with
itself using its complete PCM directory passed the comparator's finite sample,
frame count, fingerprint and PCM checks. Requested sample rates were reported
exactly. Complete held-plus-tail output contained 64 frames at 12000 Hz and
768 frames at 192000 Hz, consistent with rounding each interval upward to
32-frame engine blocks. Both repetitions had matching fingerprints.

These tiny idle fixtures validate CLI boundaries and evidence structure. Their
timings are not CPU-performance evidence and their silence does not validate
musical sound preservation.
