# Wave 9, agent 50 — structure layout review

Role: systems engineer and VST cache/locality specialist.

## Finding

A temporary append-only arrangement restores the original sampled member offsets
and the original `SurgeStorage` and `SurgeSynthesizer` sizes on the available GNU
x86_64 target. **This establishes a layout opportunity, not a CPU improvement or
the cause of any observed timing regression.** After this review, the coordinator
authorized applying the measured append-only placement to four production headers.

The original storage object ends its `noiseRng` at byte 924,136 and has eight bytes
of alignment padding before its 924,144-byte boundary. Moving the new 64-bit
generation counter to the end consumes that gap. The currently published insertion
before `samplerate` shifts later storage state and enlarges storage and the enclosing
synthesizer by 16 bytes.

Moving the three effects' cache fields after their original data members also
restores the sampled original history/counter offsets. Their new total sizes remain
the same as the current candidate because the caches still require storage.

## Method and scope

Read `AGENTS.md`, the current headers and recorded effective compiler commands.
Compiled three small translation units to assembly with GNU C++ 14.2.0, matching
the recorded definitions/include paths, C++20 and SSE settings. No code was linked
or executed; no engine build or benchmark was run. `-fno-access-control` allowed
private-member introspection only and did not modify header access declarations.
The compiler's conditionally-supported non-standard-layout `offsetof` diagnostics
were retained. An initial assembly parsing count assertion failed because it read
past the array; parsing was corrected without another compilation.

The overlay moves only the existing new declarations: the generation counter goes
after the original storage data, Conditioner caches follow `gain`, and EQ caches
follow `bi`. All checked old offsets match baseline in this overlay. It also
retains the original storage construction rule: every member is initialized before
the constructor body invokes `init_tables()`.

## Bounded recommendation

If render-thread CPU results identify a regression worth isolating, append-only
placement is a concrete candidate for a controlled source change: it removes a
measured layout disturbance and reduces this target's per-instance storage size
by 16 bytes without removing cache state. Compare that revision with the current
one using identical harnesses and complete audio validation. Do not label it a
CPU fix until measured, and do not assume the eight-byte gap exists on Windows,
ARM or another standard-library ABI.

## Applied follow-up

The coordinator authorized the verified relocation after reviewing the type-only
results. Updated only `SurgeStorage.h`, `ConditionerEffect.h`,
`ParametricEQ3BandEffect.h` and `GraphicEQ11BandEffect.h`, using the exact previously
compiled overlay contents. Checked the original header hashes before writing to
preserve any concurrent work. The storage counter remains public and has its same
initializer. The effect cache fields remain private. No method, update cadence,
cache key, parameter, processing operation or reset logic changed.

`SurgeStorage` calls `setSamplerate()` and `init_tables()` in its constructor body,
after every member has initialized; moving the counter does not precede its
lifetime with those calls. The complete candidate rebuild, 63-case PCM comparison
and timing investigation remain the coordinator's work.

No commit, push, additional agent or timing claim. All type-only compilation is
finished, and production header edits are frozen. Scoped whitespace validation
passed after application.
