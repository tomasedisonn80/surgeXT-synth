checked before and after each invocation. Patch collision cases deliberately
used private sentinel files: the tested path must reject before attempting to
load an input patch. No factory content was used or changed.

For the accepted case, `thread_clock.validate_report()` verified exact scenario,
frame, sample-rate, repetition, seed and duration bindings against the wall
report. Each held/released CPU array contains two positive finite values, and its
PCM fingerprints match the two wall-report runs. The single-build complete PCM
check verified finite floats, fingerprint, SHA-256 and length:
**4,800 stereo frames / 38,400 bytes**.
Both repetitions have positive peak and RMS values.

## Scope and limits

These checks establish native sidecar argument protection and the integrity of
one build's report/clock/audio relationship. The short accepted run is not CPU
improvement evidence, a baseline/candidate comparison, a clock-accuracy
calibration, or a host deadline test. The Linux build exercised the supported
thread clock; unsupported-platform failure paths were not executed here.

Only the evidence JSON and this report were written in the repository. There
were no production edits, compilations, full benchmarks, commits, pushes or
additional agents.
