# Wave 2, agent 10 — VST output-pointer caching

## Completed changes

Changed only `src/surge-xt/SurgeSynthProcessor.cpp` and this report. The float
`processBlock` callback now obtains main output channel pointers and valid stereo
scene output pointers once per nonempty callback. The sample loop indexes those
pointers directly instead of repeatedly calling JUCE's `getWritePointer` and
checking scene channel counts.

Both existing scene clears remain before pointer acquisition. The per-sample
`activateExtraOutputs` check remains in place, so disabling extra outputs still
leaves their cleared samples untouched. The MIDI loop, engine block boundaries,
latent-input handling, input reads before output writes, bypass paths, reference
audio publication, and CLAP callback are unchanged. No pointer survives its
callback.

## Clear-state and lifetime audit

The pinned JUCE `AudioBuffer::getWritePointer` changes the local buffer's
`isClear` bookkeeping even without writing a sample. Pointer acquisition is
therefore conditional on a positive sample count; zero-length callbacks retain
the old behavior and still reach pending-MIDI and post-processing handling.
Pointers are acquired after the existing scene clears, and no local bus clear or
resize occurs between acquisition and the last sample write. Valid positive-size
scene views can be marked nonclear while extra output is disabled, but this only
changes bookkeeping on those temporary local views: the original scene clears
remain effective and no sample is written while the activation flag is false.

`getBusBuffer` creates channel views over the supplied callback buffer. Neither
MIDI application nor engine processing resizes these local views. Caching the
view's channel pointers therefore retains the original buffer addressing and
input/output aliasing order.
