# Wave 3 / Agent 13 — Conditioner coefficient inputs

Role: systems engineer and VST DSP specialist.

## Implemented

Changed only `src/common/dsp/effects/ConditionerEffect.cpp` and its header.
`setvars()` now remembers the exact bass, treble and side-highpass inputs and the
sample-rate inverse. Each band recalculates coefficients when its input changes;
an initialization or sample-rate change recalculates all three bands.

The float comparison combines numeric equality with an IEEE representation check.
It therefore distinguishes signed zero and subnormal bit patterns, including when
the plugin enables DAZ, while NaN never compares as a cache hit. The sample-rate
key likewise compares both numeric value and representation. The cache consists
only of three floats, one double and a validity flag; it introduces no allocation,
lock, lookup table, asynchronous work or parameter serialization.

## Invariants checked in source

- Pinned `sst-filters` revision
  `6bcf08bb8ecd177b161281e8147f30b10f0b5db7` implements `vlag::newValue()` as a target
  assignment. Coefficient smoothing advances inside `process_block()`, which is
  unchanged. Repeating a setter with identical inputs after its first call adds
  no smoothing step or delay-state update.
- `ConditionerEffect::init()` first suspends all three filters and then calls
  `setvars(true)`. That call always recalculates all coefficients, retaining
  `BiquadFilter::first_run` initialization semantics even when inputs equal the
  previous values. `suspend()` calls `init()` and therefore takes the same path.
- `SurgeSynthesizer::setSamplerate()` calls effect `sampleRateReset()`, whose base
  implementation is empty. The new key reads `storage->dsamplerate_inv` at every
  existing `setvars()` call, so it does not depend on a missing invalidation hook.
- Bass and treble retain their fixed frequency/bandwidth values. Their conversion
  uses the storage's tuning-independent pitch and dB tables. Highpass frequency
  still uses the original `highpass / 12.0` calculation and Q of `0.4`.
- Deactivation, reactivation, bypass, ringout, gain, width, compression, metering
  and `process_only_control()` remain unchanged. A disabled band retains its
  state as before, and changing its coefficient input still updates its target
  on the existing control cadence.
