## Gates and interpretation

- The CPU workflow runs Python evidence contracts, builds the three headless
  Release/LTO tools with explicit PUC Lua, then runs mask differential and native
  smoke CTest gates. It makes no baseline-equivalence or CPU-speedup assertion.
- The native workflow compiles `surge-xt-tests`, runs the five new processor
  callback cases through their `[reference-workspaces]` tags along with existing
  native tests, and separately tests embedded CLAP preset discovery. Captures
  and audio-tap/TSAN checks remain distinct gates.
- The scoring workflow validates all definitions and stages the native factory
  content, then measures its existing ten representative category fixtures,
  macros, round trips and sustained polyphony. It does not render all 1,000
  presets in an ordinary push run.
- The distribution workflow fans out after version setup into its existing
  Windows, macOS and Linux configurations. Successful packaging would not prove
  realtime deadline reliability in every DAW.

The native workflow may later commit a verified gallery only if `main` still
points to its tested SHA. Its publication job rechecks the head and uses an
ordinary push; the coordinator must preserve any resulting fast-forward.
