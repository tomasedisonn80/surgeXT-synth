# Wave 4 — Agent 23: paired performance runner

Systems engineering / VST performance tooling scope: implement the standard-library orchestration around the existing native benchmark and strict comparator. No synthesis or benchmark-source changes were made by this agent.

## Changes

- Added `scripts/performance/run_comparison.py`. Each round starts both executables with `--repetitions 1`; order alternates baseline/candidate, candidate/baseline. The default is seven rounds, with a hard limit of thirty, finite durations in `(0, 30]` seconds, sample rates from 12000 to 192000 Hz, and a 300-second timeout per child process.
- Preserves each raw JSON report and combined stdout/stderr log. Retains full PCM for the first pair only; verifies complete first-pair PCM with the existing comparator and requires matching reported audio fingerprints in every subsequent round. Produces schema-1 `baseline.json` and `candidate.json` with recomputed raw arrays, medians, ranges, and realtime percentages, plus `comparison.json` and `summary.txt`.
- Writes separate `provenance.json` with exact commands and paired order, SHA-256 identities for each executable and optional patch, current working-tree benchmark/script hashes, Git metadata when available, and OS/CPU/process-affinity context. Rechecks executable and patch hashes during the run. Refuses same-file, symlink, or hard-link executable aliases and any nonempty output directory.
- Fails on subprocess error/timeout, invalid or nonfinite reports, non-deterministic fingerprints, changed parameters/engine identity, unexpected requested fixtures, or corrupted PCM. Raw evidence and failure provenance remain available.
- Added `scripts/performance/test_run_comparison.py` with synthetic child processes and reports; no timing result from these fixtures is a performance claim.

## Example

```sh
python scripts/performance/run_comparison.py \
  --baseline /absolute/path/to/baseline/surge-cpu-bench \
  --candidate /absolute/path/to/candidate/surge-cpu-bench \
  --output-dir /absolute/path/to/new-evidence \
  --rounds 7 --seconds 2 --tail-seconds 1 --sample-rate 48000 \
  --scenario all --data /absolute/path/to/surgeXT-synth/resources/data
```

Use an absent or empty output directory. `--patch /absolute/path/to/preset.fxp` supports a loaded-preset experiment with `--scenario patch` or `all`.

## Interpretation limits

The result describes offline wall time. Alternating order reduces one directional ordering bias but does not establish exclusive CPU access, fixed clock speed, or host realtime deadline reliability. CPU metadata is descriptive. Full PCM is retained only for the first pair; subsequent equality relies on the benchmark's noncryptographic fingerprint. Current working-tree source hashes identify the harness present at invocation and do not attest how a binary was compiled. Operators must retain effective build commands and control ambient user defaults, external tuning services, and machine contention for meaningful measurements.
